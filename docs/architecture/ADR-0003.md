# ADR-0003: Split Licensing Architecture (Apache 2.0 Infrastructure, Preserved Third-Party Data Licenses)

**Status:** Accepted
**Date:** 2026-08-11
**Deciders:** Founder (Bernard Abuto), AI CTO

## Context

Since M1.1, `LICENSE` had remained an intentional, documented
placeholder ("STATUS: UNDECIDED"), pending a Founder business/legal
decision. By this point the repository contained real, substantial
content across two genuinely different categories: original Sauti
Labs infrastructure (7 frameworks, SDKs, CI, scripts, documentation)
and real third-party licensed content (131 downloaded African
Storybook Project story files across two languages, individually
licensed CC-BY or CC-BY-NC per story).

Applying a single license across both categories would either:
(a) under-share the genuinely reusable infrastructure by keeping
everything proprietary, or (b) incorrectly imply Sauti Labs could
relicense third-party content it does not own, merely because that
content is stored in this Git repository.

## Decision

Sauti Labs adopts a **split licensing architecture**:

1. **Apache License, Version 2.0** covers the infrastructure and code
   layer: `frameworks/`, `scripts/`, `.github/`, `package.json`, and
   technical documentation under `docs/` (Architecture.md, ADRs,
   Contributing.md, Development.md, Enhancements.md).

2. **Third-party content retains its original license.** Everything
   under `languages/*/corpus/`, `languages/*/speech/`,
   `languages/*/lexicon/`, `languages/*/benchmarks/` is governed by
   whatever license its original source was published under (e.g.
   CC-BY-3.0 for African Storybook Project text). Storing this
   content in the repository does not transfer ownership or relicense
   it. See `languages/LICENSE-DATA.md` for the full explanation and
   `frameworks/corpus-registry` / `frameworks/speech-registry` for
   per-source license tracking.

3. **Sauti Labs' own compiled metadata about a third-party source**
   (i.e. the registry JSON entry describing it) is itself covered by
   Apache 2.0, as original organizational work - but this is
   explicitly distinct from the underlying content that entry
   describes. `NOTICE` documents this distinction directly, since it
   is easy to conflate.

4. **Future proprietary assets** (trained model weights, and any
   other genuinely proprietary future output) are explicitly excluded
   from this decision and will be licensed separately, per-asset, when
   they exist - never assumed to inherit Apache 2.0 by default.

5. **Extensibility**: `language-program-framework`'s `template/`
   includes a `NOTICE.md` that is automatically copied into every new
   language program created via `createLanguageProgram()`, so this
   licensing boundary travels with the platform as it scales to new
   languages without requiring a human to remember to add it each time.

## Rationale

This directly implements the Manifesto's stated principle: "Open
Where It Benefits Everyone... Some technologies will remain
proprietary so that Sauti Labs can remain sustainable... Our goal is
balance. Not ideology." Open-sourcing the frameworks, schemas, and
SDKs serves the ecosystem with low competitive risk and high research
goodwill, matching Era IV's eventual "Open Research Program" and
"University Partnerships" ambitions from the Engineering Roadmap.
Meanwhile, the platform never claims rights over content it does not
own - a licensing violation risk that would undermine trust with
every future data partner and contributor.

## Consequences

**Positive:**
- Contributors and researchers can freely build on the framework
  layer immediately, under a well-understood, industry-standard
  license.
- No risk of Sauti Labs inadvertently claiming ownership or relicensing
  rights over third-party content it merely stores.
- The boundary is structurally reinforced (SDK-embedded NOTICE,
  registry-tracked per-source licensing) rather than resting on
  documentation alone matching the "architecture over policy"
  precedent set in ADR-0002.
- Future proprietary decisions (model weights, etc.) remain fully
  open, unconstrained by this decision.

**Negative:**
- Two license regimes in one repository adds a small amount of
  cognitive overhead for new contributors - mitigated by
  `languages/LICENSE-DATA.md` and prominent `NOTICE` scope callouts.
- Documentation under `docs/` is bundled into Apache 2.0 rather than
  a separate content license (e.g. CC-BY-4.0) for simplicity; if this
  proves wrong later, it can be revisited without affecting the code
  or data licensing boundaries, which are independent decisions.

## Alternatives Considered

**Single license for everything (Apache 2.0 or otherwise):**
Rejected. Would either falsely imply Sauti Labs owns relicensable
rights to third-party CC-BY/CC-BY-NC content, or force the entire
infrastructure layer to remain closed to avoid that implication.

**Formalizing the existing "All Rights Reserved" placeholder:**
Rejected. Contradicts the Manifesto's explicit commitment to
openness and would slow research/community goodwill during Era I-II
of the Engineering Roadmap for no corresponding benefit, since the
infrastructure layer carries low competitive risk if shared.

**SPDX per-file license headers across all existing source files:**
Deferred, not rejected. Common Apache 2.0 practice, but would create
a large mechanical diff across dozens of files with no functional
benefit today. Recorded as a future enhancement in
`docs/Enhancements.md` rather than executed as part of this decision.
